Roles with access

  • Owner/Admin, Manager — full CRUD on dishes and categories, import/export, availability toggle.
  • Cashier, Server/Waiter, Chef/Kitchen Staff — view only: same catalog list, but the "+ Add Dish", Import/Export, Edit/Delete links, and the Categories "+ Add Category"/Edit/Delete controls are not rendered for these roles.

Data loaded on entry

  • GET /categories, GET /menuItems?restaurantId=&page=&filters.

Every button's action + destination

  • "+ Add Dish" / row "Edit" — opens the Add/Edit Dish form shown at the bottom of this file (in the real app this is likely a modal or side panel, flattened here into one scrollable page for the wireframe).
  • Row "Delete" — confirm modal: "Delete this dish? This can't be undone."
  • Availability toggle — instant PATCH /menuItems/:id {available:false}, optimistic update, no navigation, no confirm needed (fast 86-ing during service is the point).
  • "Import CSV" / "Export CSV" — file picker / file download, toast confirmation on completion.
  • Category row "Edit" — inline rename; "Delete" — blocked with an error if dishes are still assigned to it (see error state below).
  • "+ Add Category" — inline add row.
  • Form "Save" — POST/PUT /menuItems/:id, returns to the list view with the new/updated row visible and immediately reflected in New Order's item grid.
  • Form "Cancel" — discards changes, returns to list.

Empty state

  • No dishes yet: "No dishes yet. Add your first dish to build your menu." with an "Add Dish" button.
  • No categories yet: same pattern, "Add your first category."

Error state

  • Image upload fails: "Image didn't upload — check the file and try again." (accepts JPG/PNG, under 5MB).
  • Delete category with dishes still assigned: "Move or delete the 6 dishes in this category first."
  • Form validation (missing name/price): inline field-level error text under the offending input.
