Grid syncs in real time (Socket.io) — another terminal seating/clearing a table updates this view without a refresh.

Roles with access

  • Owner/Admin, Manager — full: view, add/edit/delete tables & areas, seat/clear any table.
  • Cashier — view only: sees live grid, taps through to New Order/Settle Bill, cannot add/edit table structure.
  • Server/Waiter — create/edit table status (seat guest, mark needs-cleaning) but not structural table CRUD (rename/capacity/area change) — see sitemap open questions for this judgment call.
  • Chef/Kitchen Staff — no access; nav item hidden.

Data loaded on entry

  • GET /areas, GET /tables?areaId=&status= — subscribed via Socket.io room for the restaurant, so status changes push live.

Every button's action + destination

  • Area tab click — filters grid, no navigation.
  • "+ Add Area" — opens Add Area form (name), Owner/Manager only.
  • "+ Add Table" — opens Add Table form (name, capacity, shape, area — auto-generates QR code per PRD §3.5, even though QR ordering itself is Phase 2), Owner/Manager only.
  • Tap a Free table — opens New Order with this table pre-selected.
  • Tap an Occupied table — opens New Order resuming the existing draft/sent order for this table.
  • Tap a Reserved table — opens a quick-view popover with reservation details + "Seat Guest" button (reservation detail management itself is Phase 2; this is just the table-hold indicator carried into Phase 1 per the auto-hold note in PRD §3.7 being referenced by the grid).
  • Tap a Needs Cleaning table — shows "Mark Clean" action (Server/Cashier/Manager/Owner), returns table to Free on confirm.

Empty state

  • No tables configured yet: "No tables yet. Add your first table to start taking orders." with a single "Add Table" button (Owner/Manager).

Error state

  • Real-time sync lost: banner at top of grid — "Live updates paused — reconnecting..." Grid still shows last-known state, non-blocking.
