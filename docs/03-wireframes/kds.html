All buttons above are shown active because this mockup is set to the Chef persona. For Owner/Manager/Cashier/Server viewing this same screen, "Mark Item Ready" / "Mark All Ready" render disabled/grayed with a "(view only for this role)" label.

Roles with access

  • Chef/Kitchen Staff — full control: mark items/tickets ready.
  • Owner/Admin, Manager, Cashier, Server/Waiter — view only, same board, no ready-marking controls.

Data loaded on entry

  • GET /kots?status=sent,in-kitchen,ready initial load, then a live Socket.io subscription for the restaurant's KOT room — no polling (PRD §3.4, target <1s delivery).

Every button's action + destination

  • "Mark Item Ready" — updates that single item's status, emits a socket event to POS/Table views.
  • "Mark All Ready" — moves the whole ticket to the Ready column; table status may update in real time on Table Grid/New Order.
  • Ready-column tickets — no button; they auto-clear from the KDS queue only when "Mark Served" is actioned from the POS/New Order/Table view (PRD §3.4) — flagged as an open question on the sitemap in case the client wants a KDS-side "Served" button too for kitchens without a nearby POS.
  • Filter chips — client-side status filter, no navigation.

Empty state

  • No active tickets: "No orders in the kitchen right now." shown across all three columns.

Error state

  • Socket disconnected: banner "Live connection lost — tickets may be out of date. Reconnecting..." Board keeps last-known state, non-blocking.
