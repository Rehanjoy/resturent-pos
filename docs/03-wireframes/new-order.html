Roles with access

  • Owner/Admin, Manager, Cashier — full: browse/add items, send to kitchen, void order (with reason).
  • Server/Waiter — create/edit only: same item-adding and Send to Kitchen flow, but no "Proceed to Settle Bill" affordance anywhere on this screen (billing is Cashier/Manager/Owner only).
  • Chef/Kitchen Staff — view only, and only for orders assigned to them (their station's tickets) — no Add to Billing, no Send to Kitchen.

Data loaded on entry

  • GET /tables/:id — table context chip.
  • GET /categories, GET /menuItems?available=true&category= — item grid, refetched on category tab change.
  • GET /orders?tableId=&status=draft,sent — resumes existing draft/sent order if the table was tapped from "Occupied" state; otherwise starts a new draft order.

Every button's action + destination

  • Category tab click — filters item grid client-side/via API, no navigation.
  • Spice/add-on option chips on a card — set the customization that gets attached when "Add to Billing" is tapped.
  • "Add to Billing" — adds a line item to the right Bills rail (optimistic UI, POST /orders/:id/items); disabled + labeled "Sold Out" for unavailable (86'd) dishes.
  • Qty stepper (+/-) in Bills rail — updates line item qty + totals; decrementing to 0 removes the line.
  • Line item marked "NEW, not yet sent" — items already sent in a prior KOT are locked from qty edit; changing a sent item requires a reason (audit-logged per PRD §3.3) via an edit-reason modal, not shown here.
  • Payment method icons — pre-selects a default payment mode carried forward to Settle Bill; does not charge anything here (no payment gateway in Phase 1 — manual recording only, confirmed at Settle Bill).
  • "Send to Kitchen" — POST /orders/:id/send-kot → creates a KOT with timestamp, order status Draft/Sent → In-Kitchen; stays on this screen with the rail's status stepper and item "NEW" flags updated; the new ticket appears on Kitchen Display (KDS) in real time.
  • "Save as Draft" — saves without sending to kitchen, stays on screen.
  • "Void Order" — Owner/Manager/Cashier only; opens a confirm + mandatory reason modal (audit-logged), then returns to Table & Area Grid.

Empty state

  • Category with no dishes: "No dishes in this category yet."
  • Bills rail with nothing added: "No items added yet. Tap a dish to add it to the bill." — "Send to Kitchen" disabled until at least one item is added.

Error state

  • Send to Kitchen fails (printer/socket/connection issue): "Order not sent to kitchen — check your connection and try again." Order remains in Draft, nothing is lost.
